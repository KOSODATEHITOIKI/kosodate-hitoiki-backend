# 退会とデータの保持

退会（アカウント削除）で何が消え、何が残るか、残るデータはいつ消えるかをまとめる（Issue #20）。**決定済み**＝資料または利用者の承認で決まった要件、**暫定**＝実装上の仮の扱い。

## 1. 退会の方式（決定済み・2026-10-15）

- **取消期間は設けない**。退会したら即時に削除する。誤操作は、アプリ側の確認画面（元に戻せないことの表示）で防ぐ。
- **本人確認**は、直近5分以内のログイン。メール・Google・Appleで共通で、古いセッションを盗まれても退会できないようにする。期限が切れていたら`403`（`reason: "reauth_required"`）で、再ログインを求める。
- **運営者は、運営者の登録（`admin_users`）を外してから退会する**。登録されたままだと`409`（`reason: "operator_registered"`）。

## 2. 退会の処理

`POST /functions/v1/account-delete` `{ "confirm": true }`（詳細は[API契約](API契約.md)）。

1. 本人確認（直近のログイン）と、運営者でないことを確認する。何か違えば、この時点で何も削除しない。
2. アップロードした画像（Storageの`avatars/<user_id>/`）をすべて削除する。失敗したら、DBには触れずに`500`を返す（同じ操作を再実行できる）。
3. DB関数`withdraw_account`が、**1つのトランザクション**で、ニックネームの予約・通報の整理・関連データの削除・Authのアカウント削除を行う。途中で失敗したら全体が戻る。**何度実行しても安全**で、削除済みなら`already_deleted`を返す。

画像を先に消す理由：DBの削除が先に済むと、画像のパスを知る手がかりが消え、公開URLの画像が残ってしまうため。

## 3. 削除されるもの

| 対象 | 方法 |
|---|---|
| Authのアカウント（セッション・連携・二段階認証の登録を含む） | `auth.users`の削除 |
| プロフィール、利用規約の同意、通知設定、端末情報、再送防止キー | 外部キーのカスケード |
| 投稿、投稿についたコメント・返信・共感・保存・通知 | 外部キーのカスケード |
| 自分が他の人の投稿へしたコメント、返信、共感、保存 | 外部キーのカスケード |
| ブロック、ミュート、自分の「非表示」 | 外部キーのカスケード |
| 自分が起こした通知（他の人宛て） | 明示的に削除（`notifications.actor_id`） |
| 他の人の「非表示」のうち、消える投稿・コメントを指すもの | 明示的に削除（外部キーのない論理参照） |
| 停止の履歴（`account_restrictions`） | 外部キーのカスケード |
| アップロードしたアカウント画像 | Edge Functionが削除 |

**暫定**：自分のコメントに他の人がつけた返信も、コメントと一緒に消える（親コメントの削除は返信ごとのカスケード）。単独のコメント削除とは扱いが違う（[未決事項](未決事項.md)）。

## 4. 残るもの

| 対象 | 期間 | 内容 |
|---|---|---|
| ニックネームの予約（`nickname_reservations`） | 30日 | 他の人が使えない。期限切れは毎日削除する |
| 運営の対処の記録（`moderation_actions`） | 1年 | 対象の利用者のID・種類・理由。運営者のアカウントが消えたら`admin_id`は空 |
| 通報の記録（`reports`） | 1年 | 通報者が退会したら`reporter_id`は空。消えた投稿への未対応の通報は、対応済みにして残す |
| バックアップ | 30日 | 退会・削除済みのデータを含む。復元で再公開されない手順は#21で定める |
| Supabase・Edge Functionsのログ | 提供元の保持期間 | 本文・トークンは出さない方針（[開発・運用方針](開発・運用方針.md)） |
| OpenAI（送信前チェックで送った文章） | OpenAIの保持方針 | 退会しても、こちらから削除はできない。公開前に利用規約・プライバシーポリシーへ明記する |
| FCM（プッシュ配信） | Googleの保持方針 | 端末トークンは退会で削除する。送信済みの通知の定型文のみ |

## 5. 保持期限を過ぎた記録の削除

`purge_expired_records`を毎日18:00 UTC（日本時間の午前3時）に実行する（pg_cron）。削除するもの：1年を過ぎた対処の記録・通報の記録、期限が切れたニックネームの予約、24時間を過ぎた再送防止キー。

## 6. 未決定・今後

- 公開前に、利用規約・プライバシーポリシーへ、残るデータ（上の表）と外部サービスへ送る範囲を明記する（法務確認は別工程）。
