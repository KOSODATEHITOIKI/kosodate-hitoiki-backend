# 検索方式の実測

更新日：2026-10-14。Issue #16。投稿本文の日本語検索の方式を、実測して選んだ記録。**決定済み**：検索は未ログインでも使える、一覧は新着順のみ、コメントの本文は検索に混ぜない。**設計案**：下記の方式と閾値は実測にもとづく初期案で、データが増えたら再測定する。

## 1. 結論

**PGroonga**（`pgroonga`拡張、インデックス`posts_body_pgroonga`）を採用し、検索は`security definer`のDB関数`search_posts()`で行う。

- 日本語の検索は、「夫」「熱」「咳」「泣き」のように**1〜2文字の語が中心**。`pg_trgm`は3文字未満でインデックスを使えない。
- RLSのあるテーブルでは、`leakproof`でない演算子（PGroongaの`&@`）をインデックス条件に使えない。`public_posts`ビュー越しでは、PGroongaのインデックスが使われず全件走査になる。

## 2. 実測の条件

- ローカルのPostgreSQL 17.6（Supabaseのローカルスタック）。PGroonga 3.2.5。
- **疑似データ**：語彙（子育てで出る語40個）から組み立てた3〜12語の文。実際の投稿ではなく、語の分布は一様で、現実より「密」（一般的な語が全体の約17%に一致）。
- 100万行（方式ごとに別のテーブル）。新着順に20件取る形（`order by created_at desc, id desc limit 20`）。3回測って最小値。

## 3. 結果（100万行）

| クエリ | 拡張なし（ILIKE） | pg_trgm（NFKC正規化のGIN） | PGroonga |
|---|---|---|---|
| 稀な3文字以上の語（蕁麻疹） | 296ms（全件走査） | **0.2ms** | 12ms |
| 稀な2文字の語（麒麟） | 298ms | **802ms**（全件走査） | **12ms** |
| 稀な1文字の語（蕁） | 256ms | **711ms**（全件走査） | **12ms** |
| 一致なし | 375ms | 0.1ms | 13ms |
| 全角・半角を区別しない検索（NETA） | 331ms・**0件**（区別する） | 0.4ms | 43ms |
| 一般的な語（件数が多い） | 0.1〜0.3ms | 0.3〜0.7ms | 44〜63ms |

- `pg_trgm`のインデックスは57MB（本文の約40%）、作成8秒。PGroongaの作成は約5.5秒。
- 一般的な語は、どの方式も「新着順のインデックスを走査して20件で止まる」ため速い（密なデータの特性）。差が出るのは、稀な語・短い語。
- 拡張なしのILIKEは、全角・半角を区別するため、`NETA`で全角の`ＮＥＴＡ`に一致しない。

## 4. RLS越しの検索（重要）

| 経路 | 稀な語（20万行） | 計画 |
|---|---|---|
| 未ログインが`public_posts`ビューを検索 | **328ms** | 新着順のインデックスを走査して`Filter`で除外（PGroongaは不使用） |
| 同じ条件を、RLSなし（関数のオーナー権限）で検索 | **0.4ms** | `Bitmap Index Scan on posts_body_pgroonga` |
| 実際の`search_posts()`（未ログイン、20万行） | **9〜23ms** | PGroongaのインデックスを使用 |

このため、検索は`security definer`の関数にして、公開条件を関数の中に明示している。条件は`member_posts`・`feed_posts`と同じ意味で、`supabase/tests/post_search_test.sql`で結果の一致を検証している（差が出ると漏えいになるため）。

## 5. 検索の仕様（設計案）

- 検索語は空白（全角を含む）で区切って最大5語・全体で100文字まで。全ての語を含む投稿を探す（AND）。各語はPGroongaの`&@`（単一キーワード）で、検索構文（`列名:語`、`OR`、`-`など）は解釈されない。利用者の入力はSQLに埋め込まず、パラメータとして渡す。
- 全角・半角、英字の大文字・小文字を区別しない。半角カナは全角カナに一致する。
- 結果は新着順（人気順・関連度順にしない）。`(created_at, id)`のキーセット・ページングで、同一時刻でも重複・抜けがない。
- 絞り込み：投稿の種類、話題。件数は1〜50件（既定20）。
- 未ログインは公開投稿のみ。ログイン済みは、個人の非表示・ブロック・話題と言葉のミュートを適用する（`feed_posts`と同じ）。

## 6. 既知の制約・未検証

- **クラウドのSupabaseでPGroongaが使えるか**：**devでは確認済み**（2026-10-14、deploy-devで移行`20260930160000_post_search.sql`の適用が成功）。prodは未確認（プロジェクトが一時停止中。初回リリースのデプロイで確認する）。使えない場合は、`pg_trgm`（3文字以上は高速、1〜2文字は件数が増えると遅い）に切り替える。dev・prodでの実際の検索の速度は未測定（ローカルの実測値）。
- **英数字は単語として扱われる**：PGroongaは英数字の連なりを1語として扱うため、`neta`は`ＮＥＴＡＡＢＣ`のように別の英数字と続いた中には一致しない。日本語の検索には影響が小さい。
- **データの分布は疑似**：実際の投稿の分布・長さ・語の頻度とは異なる。公開後、実データで再測定する。
- **日本語の分かち書き・同義語は扱わない**：「夜泣き」で「夜なき」には一致しない（部分一致の方式。表記ゆれ・同義語辞書は初期版では入れない）。
- **ブロックした相手のコメント数**：一覧の`comment_count`は、ブロックした相手のコメントを含む。
