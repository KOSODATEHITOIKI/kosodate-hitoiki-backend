## 2. 個人情報保護法の改正（令和8年）

個人情報保護委員会の法案の資料（2026年4月）【公式】と、解説記事【2次】から、このアプリに関係しそうな点。

| 改正の内容 | このアプリへの影響 |
|---|---|
| **16歳未満が本人のとき、同意の取得・通知は、法定代理人が対象**。未成年者の最善の利益を優先して考慮する責務【公式（法案）】 | **利用者の年齢制限が、未決定**。16歳未満が使える状態だと、親の同意などの規律が、かかる。**初期は、16歳以上（または18歳以上）に限定する**のが、現実的（6節） |
| **漏えい等の発生時、本人の権利利益の保護に欠けるおそれが少ない場合は、本人への通知の義務を緩和**【公式（法案）】 | 通知の要否の判断に、影響する。最新の条文・ガイドラインで確認 |
| **データ処理などを委託された事業者の義務を、明文化**（委託の範囲を超えて取り扱ってはならない）【公式（法案）】 | Supabase・OpenAI・Resend など、委託先との関係の整理に関係する（7節） |
| **課徴金制度の導入**（大量の個人情報の、悪質で重大な違反が対象）、罰則の強化【公式（法案）】 | 小さなサービスが、直ちに対象になる想定ではない。ただし、備える |
| **要配慮個人情報・第三者提供の同意の例外の拡大**（統計作成など）【公式（法案）】 | 現時点では、この例外に頼らない |
| 公布日・施行日 | **2026年7月17日に公布**（令和8年法律第56号）、**一部の罰則は2027年1月17日**、**本体は、公布から2年を超えない範囲で政令で定める日**【2次】。**公式の、公布後の資料で、確認する** |

## 3. 漏えい等の報告・本人への通知（事故が起きたとき）

個人情報保護委員会の公式ページ【公式】より。

**報告が義務になる「報告対象事態」**（どれか1つに当たれば、報告の対象）

| 類型 | 条件 |
|---|---|
| **要配慮個人情報**の漏えい等 | **人数の条件はない**（1人でも対象） |
| 財産的被害のおそれ | 不正利用により、財産的被害が生じるおそれがある個人データの漏えい等 |
| 不正の目的によるおそれ | 不正アクセスなど。従業者でない第三者（盗難など）も含む |
| 本人の数が多い | **1,000人を超える**個人データに係る本人の漏えい等 |

**期限**【公式】

- **速報**：発覚したら、まず速やかに。**発覚日から3〜5日以内が目安**。
- **確報**：**発覚日から30日以内**。
- 不正の目的で行われたおそれがある場合は、**発覚日から60日以内**。ページには、これが確報の期限を指すのか、報告全体の期限を指すのか、**明記されていない**。
- 日数を、暦日で数えるか、営業日で数えるかは、ページに記載がない。解説では、土日・祝日を含むとされる【2次】。**安全側に、暦日で数える**。
- 「72時間」はEUの規則の期限で、日本の期限ではない【2次】。

本人への通知：

- 上の事態（法施行規則第7条各号）を**知ったとき**に、本人へ通知する義務がある【公式（FAQ）】。
- 通知が困難な場合は、**本人の権利利益を保護するために必要な代替措置**（例：事案の公表）でよい【公式（FAQ）】。
- **通知の内容・方法・期限の目安は、ガイドライン（通則編3-5-4）で確認する**。今回、条文そのものは、読めていない。

**報告の方法**【公式】

- 民間事業者は、**個人情報保護委員会の報告フォーム**から。
- **ランサムウェア事案**は、共通様式（Excel）を、メールで提出（令和7年10月1日以降）。**その他のサイバー攻撃等の事案も、共通様式（令和8年10月1日以降。今は、使える）**。メールの宛先・件名の指定は、公式ページで確認する。
- 委託先とのやり取り・クラウド事業者による代行報告の例も、公式ページにある。

### このアプリへの当てはめ（重要）

- 投稿・自己紹介には、**病気・障害・心の不調**など、**要配慮個人情報**にあたる内容を、利用者が書き込む可能性がある（子どもの病気、自分のうつ、など）。**書き込まれていれば、1人分の漏えいでも、報告の対象になり得る。**
- **「利用者が、まだ少ない」ことは、報告を避ける理由にならない**（要配慮個人情報には、人数の条件がない）。
- **個人事業主も、報告の義務を負う**【2次】。

## 4. 要配慮個人情報（病歴など）

- 信仰・病歴・犯罪歴など、差別につながり得る情報を、**取得するには、原則として、本人の同意が必要**（法第20条第2項）【公式（法案資料に記載）】。例外あり（生命・身体・財産の保護のため、同意が困難なときなど）。
- 利用者が、**自分の意思で、投稿に病歴などを書く**場合の整理は、今回の調べでは、**直接の資料が見つからなかった**【未確認】。公開されている要配慮個人情報を取得する例外があるとされるが、**この場面に当てはまるかは、専門家に確認する**。
- **安全側の対応案**（要確認）：①利用規約・プライバシーポリシーに、「健康に関する情報などを書き込むことがあり、運営が取り扱う」旨を書き、**登録時に、同意を取る**（同意の記録は、すでに`terms_acceptances`にある）。②投稿の入力画面に、「個人が特定される情報・健康情報は、必要な範囲で」といった注意を出す。③送信前チェックで、個人情報（電話番号など）は、すでに止めている。
- **第三者提供**：要配慮個人情報は、本人の求めによる停止を条件とする第三者提供（オプトアウト）ができない【公式（法案資料に記載）】。

## 6. 子ども・年齢

- 改正で、**16歳未満は、同意・通知の対象が、法定代理人**になる見込み（2節）。現行のガイドラインでも、**12〜15歳以下は、法定代理人の同意が必要**とされる【公式（法案資料に記載）】。
- このアプリは、**子どもを育てる大人**向け。ただし、**利用者自身の年齢制限は、未決定**（[未決事項](未決事項.md)）。
- **おすすめ**：初期は、**「16歳以上」（または18歳以上）のみ**を対象とし、**利用規約で明記**し、登録時に、**年齢の確認（自己申告のチェック）**を入れる。16歳未満を、設計に入れると、親の同意の仕組みが、要る。**決めるのは、運営**。

## 7. 外国にある第三者・委託・クラウド

個人情報保護委員会のFAQ【公式】：

- クラウド事業者が、**契約上、個人データを取り扱わない**ことになっている場合は、第三者への「提供」に**当たらない**。ただし、**自ら適切な安全管理措置を講じる**必要がある。
- **外的環境の把握**：外国で個人データを取り扱う場合、**その国の個人情報保護の制度などを把握して**、安全管理のために必要な措置を講じる。日本国内のサーバーでも同様。
- **保有個人データの安全管理措置として、本人が知り得る状態に置く**：クラウド事業者の所在国、サーバーの所在国、制度を把握して講じた措置。所在国が特定できない場合は、その旨と理由。
- 「提供」に当たる場合の、本人の同意・情報提供の要件は、このFAQには、**書かれていない**。

| サービス | 渡す個人情報 | 確認すること（**未確認**） |
|---|---|---|
| **Supabase**（DB・認証・Edge Functions） | すべて（メール・投稿など） | プロジェクトのリージョン（所在国）。利用規約・DPA（データ処理契約）で、運営のデータを、Supabaseが、独自に使わないか |
| **OpenAI**（送信前チェック。Moderation API） | **投稿・コメント・自己紹介・ニックネームの本文**、アカウント画像（保存前） | API経由の入力を、学習・保存に使うか、保存期間。米国への提供に当たるか。**要配慮個人情報を含み得る本文を送る**点 |
| **Resend**（メール送信） | メールアドレス、メール本文（確認・再設定のリンク） | 所在国、保存期間、利用規約・DPA |
| **Firebase／FCM**（プッシュ） | 端末のトークン | 所在国、利用規約・DPA。**プッシュの本文には、投稿・コメントの内容を含めない**設計（実装済み） |
| Cloudflare（ドメイン・DNS） | 登録者の連絡先（WHOISは伏せ字） | 個人情報の取り扱い |
| GitHub | **個人情報は置かない**（コード・設計資料のみ。鍵は置かない運用） | — |

## 8. 外部送信規律（電気通信事業法）

総務省のページ【公式。ページの一部が文字化けして、読めない箇所がある】：

- **対象**：ウェブサイト・アプリを通じて、**電気通信サービス**（メッセージ・SNS、検索、広告など）を提供する電気通信事業者が、**利用者の情報を外部へ送る**場合。**2023年6月16日施行**。
- **通知・公表する事項**：送る情報の内容、利用目的（送信先の名称）、オプトアウトの方法（オプトアウトを使う場合）。見つけやすく、日本語で。
- **例外**：サービスの提供に必要な情報（OSの種類、画面・言語の設定、セキュリティなど）。**どこまでが例外かは、ガイダンス（第2版 2024年4月）で確認する**。
- 自社の個人ブログなどは、対象外。

**このアプリへの当てはめ**：①端末のトークンを、FCM（Google）へ渡す。②**解析・クラッシュ収集のSDK（Firebase Analytics・Crashlytics など）や、広告を入れるなら、対象になる**。**現状、フロントに、そのようなSDKがあるかは、未確認**。③自社のSupabaseへの通信は、外部への送信とは、別の扱いと思われる【一般】。**入れる前に、必ず、確認する**。

## 9. 電気通信事業の届出

- 2022年の改正で、**SNS・掲示板にあたる「媒介相当電気通信役務」**は、**届出が不要な事業（第三号事業）から除外**され、**届出の対象**になった。**ただし、省令で定める、利用者の利益への影響が大きいものに限る**【2次。総務省のガイドブックに、項目あり】。
- **このアプリが、届出の対象に当たるか**は、**未確認**。判断の材料は、①他人の通信を「媒介」するか（投稿・コメントの公開は、どう扱われるか。DMは、ない） ②省令の基準（利用者数・利用状況）。
- **次**：総務省の「電気通信事業参入マニュアル（追補版）ガイドブック」の、該当項目と、省令の基準（施行規則第59条の3）を確認し、**管轄の総合通信局に相談する**。

## 10. 投稿の削除・通報への対応（情報流通プラットフォーム対処法）

- **大規模事業者**（平均月間発信者数1,000万人など）に、削除申出の窓口・対応・基準の公表などの義務【2次】。**このアプリは、対象外の見込み**。
- ただし、**誹謗中傷・権利侵害への対応窓口は、あるべき**。すでに、通報・運営の対処・送信前チェックを、実装済み。**発信者情報の開示を求められたとき**（裁判所の手続など）の、対応の流れは、**未整備**（弁護士に相談）。
- 参考：プラットフォームの透明性（削除基準の公表）を、利用規約・ガイドラインに書いておくと、運営の判断の根拠になる。

## 11. アプリストアの規約

- **Apple**：アカウントを作れるアプリは、**アプリ内で、アカウントの削除を始められる**こと。本人確認の手順（メールの確認コードなど）は、置いてよい【公式】。**退会機能は、実装済み**（直近5分以内の再ログインを求める）。サポートへの連絡だけでは足りない、とされる【公式】。
- **Google Play**：データの削除に関する申告（Data safety）、アカウント削除の要件【**未確認**】。
- **Appleでサインイン**：Googleなどのログインを出す場合の要件（ガイドライン4.8）【**未確認**】。**フェーズ2に延期中**（[未決事項](未決事項.md)）。
- **プライバシーに関する申告**（AppleのプライバシーラベルなどGoogleのData safety）：取得する情報・第三者との共有を、申告する【一般】。**この資料の、5・7節が、そのまま材料になる**。
